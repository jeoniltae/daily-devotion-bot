# daily-devotion-bot

구글 스프레드시트에 미리 적어둔 기독교 묵상글을 **매일 아침 텔레그램 채널로 한 편씩 자동 발송**하는 봇입니다.
사람이 매일 손댈 필요 없이, 등록된 글이 순서대로 나갑니다. 무료·비상업 프로젝트입니다.

## 동작 방식

```
구글 스프레드시트 ──► GitHub Actions (월~토 cron) ──► 텔레그램 채널
   (글 저장소)          발송 스크립트 (Node/TS)
                        ├─ 다음 글 1편 선택
                        ├─ 메시지 조립·발송
                        └─ status / sentAt 갱신
```

- **발송 시각** — 월~토 한국시간 아침 7시 전후. 일요일은 쉽니다.
- **발송 순서** — `status` 가 `대기`(또는 빈 값)인 행 중 `id` 가 가장 작은 글.
- **발송 후** — 해당 행의 `status` 를 `발송됨`, `sentAt` 에 발송 시각(KST)을 기록합니다. 재실행해도 중복 발송되지 않습니다.
- **문제가 생기면** — `body` 가 빈 행은 건너뛰고, 보낼 글이 없거나 시트 갱신에 실패하면 워크플로를 실패시켜 GitHub 알림 메일로 알립니다.

## 스프레드시트 구조

시트 탭 이름은 `devotions`, 1행은 헤더, 2행부터 한 행이 하루치 글입니다.

| 컬럼        | 필수 | 설명                                         |
| ----------- | :--: | -------------------------------------------- |
| `id`        |  O   | 발송 순서 (작은 번호부터)                    |
| `title`     |      | 제목 — 있으면 굵게 표시                      |
| `verseRef`  |      | 성경 구절 표기 (예: `엡 2:8-9`)              |
| `verseText` |      | 성경 본문                                    |
| `body`      |  O   | 묵상 본문 — 비어 있으면 발송하지 않음        |
| `source`    |      | 출처 (예: `직접 작성`)                       |
| `status`    |      | `대기` / `발송됨` — 빈 값은 `대기`           |
| `sentAt`    |      | 발송 시각 — 스크립트가 자동 기록             |

비어 있는 선택 항목은 메시지에서 자연스럽게 빠집니다.

## 기술 스택

- **Node.js 24** — TypeScript 를 네이티브로 실행 (별도 빌드·`tsx` 없음)
- **googleapis** — 서비스 계정으로 시트 읽기/쓰기
- **텔레그램 Bot API** — 내장 `fetch` 로 `sendMessage` 호출 (라이브러리 없음)
- **GitHub Actions** — 스케줄러

## 프로젝트 구조

```
src/
  send.ts       진입점 — 선택 → 조립 → 발송 → 시트 갱신
  sheets.ts     구글 시트 읽기 / 발송 상태 기록
  message.ts    묵상글을 텔레그램 HTML 메시지로 조립
  telegram.ts   sendMessage 호출
.github/workflows/
  daily.yml     매일 발송 (schedule + 수동 실행)
  keepalive.yml 60일 비활성으로 예약 워크플로가 꺼지지 않게 유지
```

## 직접 운영하기

### 1. 준비물

1. **텔레그램 봇** — `@BotFather` 에서 봇을 만들고 토큰을 받습니다.
2. **텔레그램 채널** — 채널을 만들고 봇을 **관리자로 추가**합니다. 처음에는 비공개 테스트 채널을 권장합니다.
3. **구글 서비스 계정** — Google Cloud 에서 서비스 계정과 JSON 키를 만들고, Sheets API 를 활성화합니다.
4. **스프레드시트** — 위 구조대로 만들고 서비스 계정 이메일에 **편집 권한**을 공유합니다.

### 2. 로컬 실행

```bash
npm ci
cp .env.example .env   # 값을 채웁니다. 채널 ID 는 테스트 채널로.
npm run send           # 실제로 1편이 발송됩니다
npm run typecheck      # 타입 검사
```

서비스 계정 키는 `secrets/service-account.json` 에 둡니다. `.env` 와 `secrets/` 는 `.gitignore` 로 커밋되지 않습니다.

### 3. GitHub Actions 설정

저장소 **Settings → Secrets and variables → Actions** 에 4개를 등록합니다.

| Secret                        | 값                                    |
| ----------------------------- | ------------------------------------- |
| `TELEGRAM_BOT_TOKEN`          | 봇 토큰                               |
| `TELEGRAM_CHANNEL_ID`         | 발송 대상 채널 ID (`-100…`)           |
| `GOOGLE_SHEET_ID`             | 시트 URL 의 `/d/` 와 `/edit` 사이 값  |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | 서비스 계정 키 JSON **전문**          |

등록 후 Actions 탭에서 `묵상글 발송` 을 수동 실행(Run workflow)해 한 번 확인합니다.

## 알아둘 점

- **GitHub 의 예약 실행은 정시를 보장하지 않습니다.** 평소 약 55분 늦게 실행되므로 예약을 KST 06:15 에 두어 7시 전후에 도착하게 했습니다. GitHub 장애 시에는 몇 시간 밀리거나 빠질 수 있지만, `id` 순서로 발송하므로 다음 실행이 이어서 보냅니다.
- **토큰·키는 코드와 로그에 남기지 않습니다.** 공개 저장소라 Actions 로그가 모두 공개되기 때문입니다. 발송 워크플로에는 `pull_request` 계열 트리거를 두지 않습니다.
- **저작권** — 채널에 올라간 글은 공개 아카이브로 영구히 남습니다. 성경 번역본과 묵상 글의 이용 권리를 확인한 뒤 사용하세요.
